# Свой Сервис

Сайт-лендинг для приёма заявок на ремонт бытовой техники (холодильники,
стиральные и посудомоечные машины, а также другая техника). Заявки с формы
на сайте приходят прямо в Telegram.

## Стек

- [Next.js 14](https://nextjs.org/) (App Router) + React + TypeScript
- Tailwind CSS
- API-роут `/api/order`, который отправляет заявку в Telegram-бота

## Быстрый старт

```bash
npm install
cp .env.example .env.local   # заполните переменные, см. ниже
npm run dev
```

Сайт будет доступен на http://localhost:3000

## Настройка Telegram-бота (куда приходят заявки)

1. В Telegram напишите **@BotFather**, отправьте `/newbot` и следуйте
   инструкциям — получите `TELEGRAM_BOT_TOKEN`.
2. Узнайте свой `chat_id`: напишите боту **@userinfobot**, он пришлёт ваш
   ID в ответ.
3. Обязательно напишите **своему новому боту** любое сообщение (например
   "старт") — иначе он не сможет писать вам первым.
4. Впишите оба значения в `.env.local`:

   ```
   TELEGRAM_BOT_TOKEN=123456:AA...
   TELEGRAM_CHAT_ID=123456789
   ```

Если вы хотите, чтобы заявки приходили не лично вам, а в группу/канал —
добавьте бота туда администратором и укажите ID группы (она начинается с
`-100...`) в `TELEGRAM_CHAT_ID`.

## Переменные окружения

Смотрите `.env.example`:

- `TELEGRAM_BOT_TOKEN` — токен бота
- `TELEGRAM_CHAT_ID` — куда слать заявки
- `NEXT_PUBLIC_SITE_URL` — боевой адрес сайта (https://zel-servis.ru).
  От него зависят sitemap.xml, robots.txt, llms.txt и микроразметка
  schema.org — на боевом хостинге обязателен
- `NEXT_PUBLIC_PREVIEW` — режим превью (noindex + баннер). Задан только
  в workflow для GitHub Pages; на боевом хостинге не задавать

## Данные компании (адрес, телефоны, часы работы)

Название, адрес, часы работы, телефоны мастеров, ссылки на Telegram и
Яндекс.Карты, прайс и отзывы хранятся в одном месте — `lib/business.ts`. Эти значения **должны дословно совпадать** с карточкой
на Яндекс.Картах («Много Техники», Жилинская ул., 13, стр. 1, рп.
Андреевка) — совпадение имени/адреса/телефона (NAP) важно и для доверия
клиентов, и для локального SEO. Меняете что-то на Яндекс.Картах — не
забудьте поправить и здесь.

## Что нужно донастроить перед запуском в бой

- [ ] Заполнить `TELEGRAM_BOT_TOKEN` / `TELEGRAM_CHAT_ID` в переменных
      окружения на хостинге (в репозиторий они не попадают)
- [ ] Прописать `NEXT_PUBLIC_SITE_URL=https://zel-servis.ru`
- [ ] Убедиться, что `NEXT_PUBLIC_PREVIEW` на боевом **не** задан —
      иначе сайт останется закрытым от индексации
- [ ] При желании — добавить свои логотип/цвета в `tailwind.config.ts`

## Живой предпросмотр на GitHub Pages

Пока не куплен домен/хостинг, смотреть изменения можно прямо тут:
**https://zzxc26489-max.github.io/svoi_servis/**

Как это устроено:

- При каждом пуше в ветку разработки GitHub Actions
  (`.github/workflows/deploy-pages.yml`) собирает сайт в статический
  экспорт и публикует его на GitHub Pages — обычно 1–2 минуты.
- GitHub Pages отдаёт только статику, поэтому в этой сборке `/api/order`
  (отправка в Telegram) отключён — сверху показывается жёлтый баннер
  «Предпросмотр...», а сама форма при отправке покажет ошибку. Это
  ожидаемо: реальная отправка заявок заработает на боевом хостинге
  (Beget с Node.js), где серверный код снова работает.
- Предпросмотр закрыт от индексации (`noindex`), чтобы не конкурировать
  с будущим боевым доменом в поиске.

**Разовая настройка на стороне GitHub** (если ещё не сделано): в
репозитории → Settings → Pages → Build and deployment → Source
выбрать **GitHub Actions**. После этого workflow сможет публиковать
сайт самостоятельно.

Собрать такую же сборку локально:

```bash
GITHUB_PAGES=true NEXT_PUBLIC_PREVIEW=true npm run build
npx serve out
```

## Деплой

Боевой адрес — **https://zel-servis.ru**, сервер — VPS Beget с Ubuntu.
Пошаговая инструкция (настройка сервера, systemd, Nginx, SSL,
автодеплой) вынесена в отдельный файл: **[DEPLOY.md](DEPLOY.md)**.

Коротко о том, как это устроено:

- Проект собирается **в GitHub Actions**, а не на сервере: у VPS 1 ГБ
  памяти, и сборка Next.js там может упасть по нехватке памяти.
- На сервер уезжает `standalone`-бандл — около 50 МБ вместо 464 МБ
  зависимостей. Сервер только запускает готовое.
- Vercel сознательно не используем: через форму идут телефоны клиентов,
  то есть персональные данные — держать их на зарубежном сервере не
  хотим.

Два других сайта владельца («Сатис», мастерская Веры) — статические и
живут на том же VPS: Nginx отдаёт их файлы напрямую. Обычный хостинг
Beget отключён, он стоил 740 ₽/мес за то, что Nginx делает бесплатно.

## Структура проекта

```
app/
  page.tsx           — главная страница (сборка всех секций)
  layout.tsx         — общий layout, метаданные (SEO)
  api/order/route.ts — приём заявок и отправка в Telegram
components/          — секции лендинга (Hero, Services, форма и т.д.)
lib/telegram.ts      — работа с Telegram Bot API
lib/business.ts      — адрес, часы работы, телефоны мастеров (сверять с Я.Картами)
lib/structuredData.ts — микроразметка schema.org для поисковиков
```

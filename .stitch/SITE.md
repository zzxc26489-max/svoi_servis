# Project Vision & Constitution

> **AGENT INSTRUCTION:** Read this file before every итерация Stitch Loop.
> Это «долговременная память» проекта.

## 0. Важно: архитектура этого проекта — НЕ статические HTML-страницы

Скилл `stitch-loop` по умолчанию рассчитан на мультистраничный статический
сайт (`site/public/{page}.html`). **Свой Сервис — не такой сайт.** Это
Next.js 16 (App Router) + TypeScript + Tailwind, одна страница
(`app/page.tsx`), собранная из React-компонентов-секций
(`components/Hero.tsx`, `components/Services.tsx` и т.д.), а данные
компании живут в одном файле `lib/business.ts`.

**Как использовать Stitch Loop здесь правильно:**
- Генерировать через Stitch — макет/направление ОДНОЙ секции за раз
  (не всю страницу и не отдельный `.html`-файл).
- Результат (`.stitch/designs/{page}.html` + `.png`) — это референс
  вёрстки и вайба, а не файл для прямой заливки в `site/public/`.
- Перенос в код — вручную (или следующей итерацией агента): взять
  layout/spacing/типографику из сгенерированного макета и выразить их
  через существующие Tailwind-классы/`app/globals.css`-утилиты
  (`.btn-primary`, `.card`, `.section` и т.д.), не создавая новый файл
  вне `components/`.
- Тексты, цены, отзывы, телефоны — НИКОГДА не брать из Stitch-генерации.
  Единственный источник — `lib/business.ts`. Если Stitch предлагает
  «10 лет опыта» или похожую цифру — это выдумка модели, игнорировать.
- Реальных фото у бизнеса пока нет (см. `PROJECT.md` → «Ждём от
  владельца») — Stitch-макеты с фото людей/техники использовать только
  как референс композиции, не как готовый ассет.

## 1. Core Identity

* **Project Name:** Свой Сервис (сайт) / «Много Техники» (юрлицо на
  вывеске и Яндекс.Картах)
* **Stitch Project ID:** не создан — генерации через Stitch MCP в этой
  сессии не запускались, ID появится после первого реального прогона
* **Mission:** превратить визит на сайт в звонок или заявку. Это не
  каталог и не имиджевый сайт — единственная метрика успеха — телефон
  зазвонил или пришло сообщение в Telegram/WhatsApp.
* **Target Audience:** взрослые 30–70 лет, разной степени владения
  смартфоном. У старшей границы диапазона — крупный текст, минимум
  полей для заполнения, явные кнопки звонка, никакого «айтишного»
  жаргона. У младшей — ожидание, что сайт выглядит не хуже, чем у
  конкурентов, и что можно написать в мессенджер вместо звонка.
* **Voice:** прямой, честный, «свой мастер», без хайпа и без цифр,
  которые нельзя подтвердить. Реальные цены и реальный рейтинг вместо
  общих фраз («лучшие», «топ-1»).

## 2. Visual Language

* **The "Vibe" (Adjectives):**
    * *Primary:* добротный, «трейд»-премиум (мастерская, а не офис)
    * *Secondary:* спокойный, честный, без кричащих распродаж
    * *Tertiary:* тёплый акцент (оранжевый) на холодной тёмной базе —
      контраст «инструмент + огонь горелки»

Полная палитра, шрифты и компонентные стили — в `.stitch/DESIGN.md`
(взяты из `tailwind.config.ts` и `app/globals.css`, ничего не
придумано заново).

## 3. Architecture & File Structure

* **Реальный root:** `app/`, `components/`, `lib/business.ts`
* **Asset Flow:** Stitch генерирует в `.stitch/designs/` → смотрим,
  берём то, что подходит по вайбу → выражаем вручную через Tailwind в
  нужном `components/*.tsx` → проверяем `npm run lint && npm run build`
  и скриншотом (см. `PROJECT.md` → раздел 7)
* **Navigation Strategy:** одна страница, якорные ссылки в `Header.tsx`
  (`#services`, `#prices`, `#reviews`, `#how-it-works`, `#faq`)

## 5. The Roadmap (Backlog)

### Ждём реальных данных от владельца (см. `PROJECT.md` §5)
- [ ] Заменить временные сгенерированные фото в `Works` на настоящие
- [ ] Срок гарантии цифрой, стаж, входит ли диагностика в ремонт —
      как только известно, сразу в `lib/business.ts`, не в Stitch

### Идеи по воронке и доверию — обсудить с владельцем перед вводом
(не делать без подтверждения — это уже точечные правки кода, не Stitch)
- [ ] Липкая мобильная кнопка «Позвонить» — не даёт потерять номер при
      скролле длинной страницы, особенно важно для 30–70 аудитории,
      которая может не долистать до футера
- [ ] Честный «живой» триггер вместо выдуманной срочности: «Сегодня
      принимаем заявки до 22:00» по реальному времени и реальному
      режиму работы из `lib/business.ts`
- [ ] Проверить, что порядок секций уже сам по себе — воронка (оффер →
      что чиним → цены → как проходит → доказательства → отзывы →
      цифры доверия → форма → вопросы → CTA): похоже, что да, менять
      порядок не нужно, но стоит перепроверить на реальных пользователях
      30–70 лет (не на глаз дизайнера)

## 6. Creative Freedom Guidelines

1. **Оставаться в тоне:** честно, без выдуманных цифр и кейсов
   (см. `CLAUDE.md` и `PROJECT.md` — это не пожелание, а жёсткое
   правило репозитория)
2. **Каждая новая секция должна вести к звонку/заявке**, а не быть
   декором
3. **Технику именования:** секции — PascalCase-компоненты в
   `components/`, не `.html`-файлы

## 7. Rules of Engagement

1. Не пересоздавать секции из раздела 4 — уточнять существующий код
2. Никогда не переносить в `lib/business.ts` цифры/факты, придуманные
   Stitch-генерацией — только подтверждённые владельцем
3. Каждую итерацию проверять `npm run lint && npm run build` перед тем,
   как считать её завершённой (см. `PROJECT.md` §7)

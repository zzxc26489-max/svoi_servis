# Принципы разработки в этом репозитории

Источник: адаптировано из github.com/forrestchang/andrej-karpathy-skills
(сторонний проект, вдохновлённый постом Andrej Karpathy про типичные
ошибки LLM в кодинге — не официальный продукт Karpathy).

1. **Сначала думать, потом писать код.** Если из задачи не ясно, что
   именно нужно, — не гадать и не додумывать самому: уточнить у
   пользователя или свериться с существующим кодом/данными
   (`lib/business.ts` и т.п.), а не изобретать значения.
2. **Простота прежде всего.** Минимальный код, который решает задачу.
   Не добавлять абстракции, зависимости или инфраструктуру «на
   будущее», если сейчас в этом нет нужды.
3. **Точечные правки.** Менять только то, что относится к задаче. Не
   рефакторить соседний код заодно, даже если он кажется неидеальным —
   для этого отдельная задача.
4. **Ориентир на результат.** Перед тем как считать задачу выполненной,
   явно определить критерий успеха (билд проходит, линт чист, API
   отвечает ожидаемо) и проверить его — не полагаться на то, что код
   «выглядит правильным».
